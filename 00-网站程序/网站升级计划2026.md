## 〇、现状评估（结论先行）

网站的"看得见的主干"（今日状态 / 四科主页 / 错题本 / 技能树 / 院校查询 / 数据分析）接线是完整的。真正的浪费集中在两处：

1. **一批已做好的功能被锁在孤岛里**——含一整个第二仪表盘 `/home`、一个精读页 `/intensive-reading`、一整套"测评→个性化路径→计划"、一份比现役更强的"深度分析报告"，全部无入口或深埋。
2. **数据各存各的、互相不通**——错题存在 4+ 个独立 localStorage 键（命名还不统一），数学/英语/政治三个错题本**没有持久化（刷新即丢）**，`WrongProblemsDashboard` 顶上的数字是**手写假数据**；英语进度**两套账并存**（todayStatus vs readingLog）；错题、费曼 gap、技能树、今日任务之间**零联动**。

硬事实（用于治理）：

- 95 个组件中 **7 个零引用**（DistractionControl / GamificationDashboard / MoodTracker / PomodoroTimer / PsychologyIntervention / RewardShop / PersonalReport），另有 `Header.vue`（死导航，含 3 个不存在的路由）与 **17 个 `.vue.bak` + `PlaceholderComponent.vue`** 全部未被 import。
- `StudyMethodsView.vue` **152KB** 巨型文件（第二名院校页仅 51KB），需拆分。
- `reading-questions.json` **5.88MB**、`intensive-reading.json` 1.2MB **整文件 fetch、无按年拆分**，且 5.88MB 已进 PWA `globIgnores` 不被预缓存 → **手机首开英语阅读要下 5.88MB**，是移动端最大卡顿源。`universities.json` 走静态 `import`，非懒加载。
- 双版本靠手工 `cp` 同步，漂移风险高。
- CS408 的"编程训练/思维导图"两个页签被指向占位空壳，真实代码却以 `.bak` 存在，属半成品未接上。

## 指导原则

- 手机随时能用，打开就知道干什么；网站是工具不是目的。
- 默认只本地改源文件，**不擅自 push / build / 同步桌面**，上线与同步等显式指令。
- 改 `.vue` 遵守铁律：不用 SearchReplace 改 vue，用 node 脚本尾部锚点重插 + `new Function` 验证 PASS 再写盘。
- 每个阶段结束都要 build 通过 + 截图/DOM 验证功能正常，再继续下一阶段。

目标：一份源码同时产出个人版与共享版，彻底告别手工 `cp` 与漂移。

⚠ **迁移期保护先做了（本轮，只读 diff）——结论颠覆了原方案假设：** 对 `frontend` vs `frontend-share` 全树做了哈希级分叉登记（只读，不改任何文件、不碰 git/CI）。计数：**两版共 107 个 src 文件完全相同；个人版独有 130 个 src 文件；共享版独有仅 1 个（`ShareHomeView.vue`）；34 个同名文件内容有差异。**

- **关键事实：`frontend-share` 不是"个人版去掉几个字段"的脱敏孪生，而是刻意做瘦的公开子集。** 个人版独有能力包括：整套错题系统（`WrongProblemsDashboard` + 数/英/政/DS/OS/Network 各科 `*WrongProblems.vue` + `wrongProblems.ts`）、资料进度墙（`materials.ts`/`MaterialsWall`）、今日状态仪表盘（`todayStatus.ts`/`TodayStatusView`）、数据分析（`DataAnalyticsView`）、6 个翻译模块视图、学习路径/测评/心理干预/性能/自测等子系统、`cloudSync`/`fsrs`/`srs` 云同步、以及 `public/data` 下的精读/翻译/费曼等大量私有数据。共享版这些**一概没有**。
- **因此原计划"构建时脱敏（环境变量剥离个人信息字段）"这条路走不通**——脱敏是针对"同一棵树去掉少量敏感字段"，而这里差的是**上百个模块与路由的整体功能集**。硬套 `vite build --mode share` 只会得到一个报错的构建（一堆 import 指向不存在的个人模块），不是共享版。
