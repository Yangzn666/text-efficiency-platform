## 一、导入流程概览

### 1.1 核心文件位置

```
00-网站程序/
├── backend/
│   ├── data/
│   │   └── intensive-reading-analysis.json    # 精读分析数据
│   └── index.js                                # API路由配置
```

### 1.2 导入步骤

1. **准备真题数据** - 整理题目JSON格式

5. **测试验证** - 刷新页面检查效果

## 二、传统阅读（Traditional Reading）导入

### 2.1 数据结构要求

每道传统阅读题目必须包含以下字段：

```javascript
{
  id: 唯一ID,
  year: 年份 (如 2005),
  section: "Traditional Reading",
  textNumber: Text编号 (1-4),
  article: "完整的文章HTML内容",  // ⚠️ 必需字段
  questions: [
    {
      questionNumber: 题号,
      question: "题干内容",
      options: ["A. 选项A", "B. 选项B", "C. 选项C", "D. 选项D"],
      answer: "正确答案 (A/B/C/D)",
      analysis: "解析内容"
    }
  ]
}
```

### 2.2 文章格式规范

**HTML标签要求：**
- 使用 `<p>` 标签包裹每个段落
- 段落首行缩进通过CSS自动添加（`text-indent: 2em`）
- 强调内容使用 `<u>` 标签（不会显示为红色空格）

**示例：**
```html
<p>When a monkey is underpaid, it may refuse to work.</p>
<p>This behavior suggests that <u>fairness</u> is not unique to humans.</p>
```

### 2.3 数据Key命名规则

精读数据的Key格式：
```
{年份}-Traditional Reading-{Text编号}
```

**示例：**
- `2005-Traditional Reading-1` - 2005年Text 1
- `2005-Traditional Reading-2` - 2005年Text 2
- `2010-Traditional Reading-3` - 2010年Text 3

## 三、完形填空（Use of English）导入

### 3.1 数据结构要求

```javascript
{
  id: 唯一ID,
  year: 年份 (如 2005),
  section: "Use of English",
  article: "完整的文章HTML内容",  // ⚠️ 必需字段
  questions: [
    {
      questionNumber: 题号 (1-20),
      blank: "空格前的上下文",
      options: ["A. 选项A", "B. 选项B", "C. 选项C", "D. 选项D"],
      answer: "正确答案",
      analysis: "解析"
    }
  ]
}
```

### 3.2 文章格式规范

**空格标记：**
- 使用 `<u>` 标签标记空格位置
- 前端会自动渲染为红色下划线样式

**示例：**
```html
<p>The human nose is an <u>underrated</u> tool.</p>
<p>Compared <u>with</u> many animals, we are often said to be weak smellers.</p>
```

### 3.3 数据Key命名规则

```
{年份}-Use of English
```

**示例：**
- `2005-Use of English`
- `2010-Use of English`

## 四、精读分析数据配置

### 4.1 文件位置

```
backend/data/intensive-reading-analysis.json
```

### 4.2 数据结构模板

```json
{
  "2005-Traditional Reading-1": {
    "theme": "主题思想（200-300字）",
    "structure": "文章结构（树形结构描述）",
    "writingTechniques": [
      "写作手法1",
      "写作手法2",
      "写作手法3"
    ],
    "readingStrategies": [
      "阅读策略1",
      "阅读策略2",
      "阅读策略3"
    ],
    "keyVocabulary": [
      {
        "word": "单词",
        "meaning": "中文释义",
        "context": "文中语境或短语"
      }
    ],
    "grammarPoints": [
      "语法要点1",
      "语法要点2"
    ],
    "examTips": [
      "考研技巧1",
      "考研技巧2"
    ]
  }
}
```

### 4.3 各字段详细说明

#### theme（主题思想）
- **长度**：200-300字
- **内容**：概括文章核心观点、研究结论、作者态度
- **示例**：
  ```
  本文通过猴子实验揭示了公平感的进化起源。文章指出，卷尾猴与人类一样，具有社会情感和公平意识...
  ```

#### structure（文章结构）
- **格式**：树形结构，使用特殊符号
- **符号说明**：
  - `├─` 分支节点
  - `└─` 最后一个分支
  - 换行分隔不同段落
- **示例**：
  ```
  第一段：引出话题
    ├─ 现象描述：人们喜欢加薪，但同事加薪更多会不满
    ├─ 传统观点：这种行为是人类特有的
    └─ 研究结论：猴子也有公平感
  
  第二段：介绍实验对象
    ├─ 研究对象：雌性棕色卷尾猴
    └─ 关键特征：关注商品和服务的价值
  ```

#### writingTechniques（写作手法）
- **数量**：4-6条
- **格式**：手法名称 + 冒号 + 具体说明
- **常见手法**：
  - 对比论证
  - 引用研究
  - 具体案例
  - 设问结尾
  - 类比手法
  - 转折论证
  - 让步论证
  - 因果分析
  - 举例说明
  - 数据支撑

#### readingStrategies（阅读策略）
- **数量**：4-6条
- **内容**：针对该类文章的阅读技巧
- **示例**：
  - 关注转折词：But、However引出核心观点
  - 识别研究引用：Nature提示科研类文章
  - 抓住实验逻辑：训练→实验→结果→结论
  - 理解类比：人类与猴子行为对比是主线
  - 注意专业术语

#### keyVocabulary（核心词汇）
- **数量**：6-10个
- **字段**：
  - `word`: 英文单词
  - `meaning`: 中文释义
  - `context`: 文中出现的语境或搭配
- **选择标准**：
  - 考研高频词汇
  - 影响理解的关键动词/形容词
  - 熟词僻义
  - 专业术语

#### grammarPoints（语法要点）
- **数量**：4-6个
- **格式**：语法名称 + 冒号 + 例句说明
- **常见语法**：
  - 形式主语/宾语
  - 定语从句（限制性/非限制性）
  - 状语从句（让步/原因/结果）
  - 比较结构
  - 插入语
  - 分词作定语/状语
  - 被动语态
  - 倒装句

#### examTips（考研技巧）
- **数量**：5-8条
- **内容**：针对该类题型的应试技巧
- **示例**：
  - 考研常考科研类文章，掌握现象-实验-结果-结论结构
  - 注意首段，通常包含主旨信息
  - 实验细节题常考，区分训练和实验阶段
  - 作者态度：客观报道，中立偏积极
  - 词义猜测：注意上下文语境和同义替换
  - 推理题：根据实验结果推断观点或意义

### 4.4 完形填空精读配置差异

完形填空的精读分析侧重点不同：

**theme**：侧重文章主旨和论证逻辑

**writingTechniques** 增加：
- 逻辑关系词的使用
- 上下文语义连贯
- 词义辨析技巧

**readingStrategies** 增加：
- 关注逻辑关系词：but/however/although
- 注意上下文语义连贯性
- 词义辨析：根据语境选择最合适的词
- 固定搭配识别

**examTips** 增加：
- 完形填空常考逻辑关系词
- 注意上下文语义连贯性
- 词义辨析：根据语境选择最合适的词
- 固定搭配：capable of/in contrast to等
- 语法结构：注意从句类型和连接词
- 语篇理解：把握文章整体逻辑脉络

### 4.5 添加新数据的步骤

1. **编辑JSON文件**
   ```bash
   # 打开文件
   backend/data/intensive-reading-analysis.json
   ```

2. **添加新条目**
   ```json
   {
     "2006-Traditional Reading-1": {
       "theme": "...",
       "structure": "...",
       ...
     }
   }
   ```

3. **验证JSON格式**
   - 确保没有语法错误
   - 使用在线JSON验证工具检查
   - 注意逗号分隔

4. **重启后端服务**
   ```bash
   cd backend
   node index.js
   ```

5. **测试API**
   ```powershell
   Invoke-WebRequest -Uri "http://localhost:3001/api/intensive-reading?key=2006-Traditional%20Reading-1" -UseBasicParsing
   ```

## 五、形近词添加

### 5.1 文件位置

```
frontend/src/components/VocabularyLearning.vue
```

### 5.2 数据结构

在 `confusableGroups` 数组中添加新组：

```javascript
{
  id: 下一个可用ID,  // 从现有最大ID+1开始
  title: 'word1 vs word2 vs word3',  // 用 vs 连接
  words: [
    { content: 'word1', translation: '释义1' },
    { content: 'word2', translation: '释义2' },
    { content: 'word3', translation: '释义3' }
  ]
}
```

### 5.3 添加示例

```javascript
{
  id: 107,
  title: 'adapt vs adopt vs adept',
  words: [
    { content: 'adapt', translation: '适应，改编' },
    { content: 'adopt', translation: '采用，收养' },
    { content: 'adept', translation: '熟练的，擅长的' }
  ]
}
```

### 5.4 注意事项

1. **ID连续性**：确保ID不重复，从最大ID+1开始
2. **title格式**：使用 `vs` 连接所有单词
3. **translation简洁**：释义要简明扼要
4. **分组原则**：
   - 拼写相似的词
   - 发音相近的词
   - 容易混淆的词
   - 同一词根的不同形式

## 六、常见问题与注意事项

### 6.1 精读数据加载失败

**问题**：控制台显示 `404 Not Found`

**原因**：
1. Key命名不正确
2. JSON文件格式错误
3. 后端服务未重启

**解决**：
```javascript
// ✅ 正确
"2005-Traditional Reading-1"

// ❌ 错误
"2005-TraditionalReading-1"  // 缺少空格
"2005-Traditional Reading"   // 缺少Text编号
```

### 6.2 文章不显示

**问题**：精读页面显示"暂无文章数据"

**原因**：题目数据中缺少 `article` 字段

**解决**：确保每道题目都有完整的article字段

### 6.3 传统阅读空格显示为红色

**问题**：传统阅读的 `<u>` 标签显示为红色空格样式

**原因**：前端条件判断失效

**解决**：检查 `IntensiveReadingView.vue` 中的条件代码：
```javascript
// 只对完形填空添加空格样式
if (section.value === 'Use of English') {
  styledArticle = styledArticle.replace(/<u>/g, '<u style="...">')
}
```

### 6.4 JSON解析错误

**问题**：`SyntaxError: Unexpected token`

**原因**：
1. JSON文件有BOM头
2. 逗号缺失或多余
3. 引号不匹配

**解决**：
```bash
# 使用Node.js重新生成无BOM的文件
node backend/generate-intensive-reading.js
```

### 6.5 数据Key匹配失败

**问题**：URL参数与数据Key不匹配

**场景**：未指定Text编号时

**解决**：前端会自动查找该年份第一个有文章的Text，并使用其textNumber构建Key

### 6.6 最佳实践

1. **数据备份**
   - 修改前备份JSON文件
   - 使用Git版本控制

2. **增量添加**
   - 一次只添加1-2篇文章的精读数据
   - 测试通过后再继续

3. **质量检查**
   - theme是否准确概括主旨
   - structure是否清晰展示层次
   - vocabulary是否选取了真正的难点词
   - examTips是否有实际指导意义

4. **一致性维护**
   - 保持相同的格式风格
   - 使用统一的标点符号
   - 遵循既定的命名规范

5. **文档更新**
   - 每次导入后更新本指南
   - 记录特殊情况和解决方案
