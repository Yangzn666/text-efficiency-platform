**新增"五、指令对齐"小节**:
```typescript
### 五、指令对齐（Instruction Alignment）⭐⭐

<a href="javascript:void(0)" onclick="showKnowledgeCard('instructionAlignment')" style="color: #409eff; text-decoration: underline; cursor: pointer; display: inline-block; margin-bottom: 12px;">
  💡 点击查看指令按字边界对齐存放详解
</a>

**定义**：指令在内存中的起始地址必须是某个固定值（如4字节、8字节）的整数倍。

**原因**：
- **提高访存效率**：对齐后一次访存即可读取完整指令
- **简化硬件设计**：不需要处理跨边界访问的复杂情况
- **避免性能损失**：未对齐访问可能需要多次访存

**示例**：
\`\`\`
假设字长为4字节（32位），指令按字边界对齐：
地址      内容
0x0000    指令1（4字节）✅ 对齐
0x0004    指令2（4字节）✅ 对齐
0x0008    指令3（4字节）✅ 对齐

如果不对齐：
0x0000    指令1的前2字节
0x0002    指令1的后2字节 + 指令2的前2字节 ❌ 跨边界
0x0004    指令2的后2字节 + ...
→ 需要两次访存才能读取完整指令，效率低！
\`\`\`

**现代处理器支持**：
- x86：支持未对齐访问（但性能会降低）
- ARM：早期版本要求严格对齐，ARMv7+支持未对齐但有性能损失
- RISC-V：通常要求对齐
```

## 🎯 知识点详细内容

### 1. 通用寄存器可编程指定多种功能

**核心概念**：
- 通用寄存器虽然叫"通用"，但程序员可以根据需要将其用于不同的用途
- 可以作为数据寄存器、地址寄存器、计数器、栈指针、基址指针等

**x86架构示例**：
- EAX：累加器 → 算术运算、函数返回值
- ECX：计数器 → 循环计数、字符串操作
- ESP：栈指针 → 栈顶管理（专用）
- EBP：基址指针 → 栈帧基址、局部变量访问

### 2. 指令寄存器对程序员完全透明

**透明的含义**：
- 程序员不能通过指令直接读取或修改IR的内容
- IR的内容完全由硬件自动控制

**为什么透明**：
- 保证正确性：防止程序员破坏指令执行流程
- 简化编程：程序员只需关心程序逻辑
- 提高效率：硬件自动控制，速度快

### 3. 指令总是根据程序计数器从主存储器中读出

**核心概念**：
- 这是冯·诺依曼体系结构的核心特征
- PC存放下一条要执行的指令地址
- CPU根据PC的值从内存中取出指令

**PC位数决定因素**：
- 按字节编址：PC位数 = log₂(存储容量/1字节)
- 按字编址：PC位数 = log₂(存储容量/字长)
- 例如：4GB存储器，按字节编址需要32位PC，按字编址（32位字长）需要30位PC

### 4. 间址周期是什么意思

**定义**：
- 当指令使用间接寻址时，在取指周期之后、执行周期之前，需要额外的一个周期来访问内存获取操作数的真正地址

**特点**：
- 不是每条指令都有，只有使用间接寻址的指令才需要
- 间接寻址需要两次访存（一次取地址，一次取操作数）
- 相比直接寻址，速度更慢

**指令周期组成**：
- 取指周期（IF）
- 间址周期（IND）← 仅在间接寻址时出现
- 执行周期（EX）
- 中断周期（INT）

### 5. 哪些寄存器是汇编语言程序员可见的

**可见的寄存器**：
- 通用寄存器：EAX、EBX、ECX、EDX、ESI、EDI、EBP、ESP
- 程序计数器PC：可通过跳转指令间接修改
- 标志寄存器PSW/FLAGS：可通过条件跳转读取标志位

**透明的寄存器**：
- 指令寄存器IR：硬件自动控制
- 存储器地址寄存器MAR：硬件自动使用
- 存储器数据寄存器MDR：硬件自动使用

### 6. 指令按字边界对齐存放是什么意思

**定义**：
- 指令在内存中的起始地址必须是某个固定值（如4字节、8字节）的整数倍

**为什么要对齐**：
- 提高访存效率：对齐后一次访存即可读取完整指令
- 简化硬件设计：不需要处理跨边界访问
- 避免性能损失：未对齐访问会有性能惩罚

**不同架构的要求**：
- x86：建议对齐（非强制），支持未对齐但性能降低
- ARM（早期）：严格对齐，不支持未对齐
- MIPS：严格对齐，不支持未对齐
- RISC-V：建议对齐

### 7. 多周期CPU的特点

**定义**：
- 不同指令可以使用不同数量的时钟周期
- 简单指令（如ADD）：1-2个周期
- 复杂指令（如MUL、DIV）：多个周期

**与单周期CPU的对比**：

| 对比维度 | 单周期CPU | 多周期CPU |
|---------|----------|----------|
| 时钟周期 | 长（等于最长指令时间） | 短（等于最短阶段时间） |
| CPI | 固定为1 | 不固定（1~多个） |
| 时钟频率 | 低 | 高 |
| 硬件利用率 | 低（简单指令浪费） | 高（可复用硬件） |
| 控制复杂度 | 简单 | 复杂（需要状态机） |
| 典型应用 | 简单嵌入式系统 | CISC架构（x86） |

**优点**：
- 时钟频率更高
- 硬件利用率高
- 适合复杂指令（CISC常用）

**缺点**：
- 控制复杂（需要状态机）
- CPI不固定，难以预测性能
- 不利于流水线
