# 第三章 存储器系统

## 3.1 存储器的分类与层次结构

### 一、存储器的分类

#### 1. 按存储介质分类
- **半导体存储器**：RAM、ROM、Flash
- **磁表面存储器**：磁盘、磁带
- **光存储器**：CD、DVD、蓝光

#### 2. 按存取方式分类
- **随机存取存储器（RAM）**：任意位置访问时间相同
- **顺序存取存储器（SAM）**：按顺序访问，如磁带
- **直接存取存储器（DAM）**：结合两者特点，如磁盘

#### 3. 按信息可保存性分类
- **易失性存储器**：断电后信息丢失（RAM）
- **非易失性存储器**：断电后信息保留（ROM、Flash、磁盘）

---

### 二、存储器的层次结构

```
CPU寄存器（最快、最小、最贵）
    ↓
高速缓存 Cache（L1 → L2 → L3）
    ↓
主存储器（内存）
    ↓
辅助存储器（磁盘、光盘）
    ↓
海量存储器（磁带库）（最慢、最大、最便宜）
```

**层次结构设计原则**：
- **速度递减**：越靠近CPU速度越快
- **容量递增**：越远离CPU容量越大
- **价格递减**：单位容量价格越低

---

## 3.2 主存储器

### 一、SRAM与DRAM的比较

| 特性 | SRAM（静态RAM） | DRAM（动态RAM） |
|------|----------------|----------------|
| 存储原理 | 触发器 | 电容电荷 |
| 刷新 | 不需要 | 需要定期刷新 |
| 速度 | 快 | 较慢 |
| 集成度 | 低 | 高 |
| 功耗 | 大 | 小 |
| 价格 | 贵 | 便宜 |
| 用途 | Cache | 主存 |

---

### 二、存储器的扩展

#### 1. 位扩展
- 增加数据位数
- 例：用8K×1位的芯片组成8K×8位的存储器
- 需要8片芯片并联

#### 2. 字扩展
- 增加存储单元数量
- 例：用8K×8位的芯片组成32K×8位的存储器
- 需要4片芯片，通过地址译码选择

#### 3. 字位同时扩展
- 同时增加字数和位数
- 例：用8K×4位的芯片组成32K×8位的存储器
- 需要8片芯片（4组，每组2片）

---

### 三、读操作与写操作的区别

#### 1. 读操作（Read Operation）
- **定义**：从存储器中取出数据
- **流程**：
  1. CPU送出地址到地址总线
  2. 存储器根据地址找到对应单元
  3. 将数据放到数据总线上
  4. CPU从数据总线读取数据
- **特点**：
  - 不改变存储单元内容
  - 属于非破坏性操作
  - 可以连续读取

#### 2. 写操作（Write Operation）
- **定义**：将数据存入存储器
- **流程**：
  1. CPU送出地址到地址总线
  2. CPU将数据放到数据总线
  3. CPU发出写控制信号
  4. 存储器将数据写入指定单元
- **特点**：
  - 会覆盖原有数据
  - 属于破坏性操作
  - 需要写使能信号

#### 3. 关键区别

| 对比项 | 读操作 | 写操作 |
|-------|--------|--------|
| **数据流向** | 存储器→CPU | CPU→存储器 |
| **控制信号** | 读使能（RD） | 写使能（WR） |
| **内容变化** | 不改变 | 覆盖原有数据 |
| **破坏性** | 非破坏性 | 破坏性 |
| **总线使用** | 数据总线输入 | 数据总线输出 |

---

### 四、存储器与CPU的连接

**关键信号线**：
- **地址线**：确定存储单元位置
- **数据线**：传输数据
- **控制线**：读/写控制、片选信号

**地址分配**：
- 高位地址用于片选
- 低位地址用于片内寻址

## 3.3 高速缓存Cache

### 一、Cache的工作原理

**局部性原理**：

#### 1. 时间局部性（Temporal Locality）
- **定义**：如果某信息被访问，那么在不久的将来它可能再次被访问
- **原因**：程序中存在循环结构、子程序调用、变量重复使用
- **例子**：
  ```c
  for (i = 0; i < 1000; i++) {
      sum = sum + array[i];  // sum变量被重复访问
  }
  ```
  - `sum`变量在每次循环中都被访问 → 时间局部性好
- **应用**：Cache缓存最近访问的数据

#### 2. 空间局部性（Spatial Locality）
- **定义**：如果某存储单元被访问，那么它附近的存储单元也可能被访问
- **原因**：程序顺序执行、数组连续存储、指令连续存放
- **例子**：
  ```c
  int array[100];
  for (i = 0; i < 100; i++) {
      sum = sum + array[i];  // 数组元素连续访问
  }
  ```
  - 访问`array[0]`后，很可能访问`array[1]`、`array[2]`... → 空间局部性好
- **应用**：Cache预取相邻数据块

#### 3. 局部性原理的度量
- **时间局部性度量**：同一数据被重复访问的时间间隔
- **空间局部性度量**：被访问数据的地址分布范围
- **良好局部性**：程序具有良好的局部性，Cache命中率高

**Cache命中率**：
$$H = \frac{N_c}{N_c + N_m}$$

其中：$N_c$为Cache命中次数，$N_m$为主存访问次数

**平均访问时间**：
$$T_a = H \times T_c + (1-H) \times T_m$$

其中：$T_c$为Cache访问时间，$T_m$为主存访问时间

---

### 二、Cache-主存映射方式

#### 1. 直接映射
- 主存块只能映射到Cache的固定位置
- **优点**：硬件简单，速度快
- **缺点**：冲突率高

**地址格式**：
```
| 标记Tag | Cache行号Index | 块内偏移Offset |
```

#### 2. 全相联映射
- 主存块可以映射到Cache的任意位置
- **优点**：冲突率最低
- **缺点**：硬件复杂，速度慢

**地址格式**：
```
| 标记Tag | 块内偏移Offset |
```

#### 3. 组相联映射
- 折中方案，将Cache分为若干组
- 主存块可以映射到对应组的任意行
- **n路组相联**：每组有n行

**地址格式**：
```
| 标记Tag | 组号Set | 块内偏移Offset |
```

**组相联映射实例**：

**例题**：设主存容量为1MB，Cache容量为16KB，每块32B，采用4路组相联映射，求地址格式。

**解题步骤**：
1. **计算块内偏移位数**：
   - 块大小 = 32B = 2^5B
   - 块内偏移 = 5位

2. **计算Cache块数**：
   - Cache容量 = 16KB = 2^14B
   - Cache块数 = 16KB / 32B = 512块

3. **计算组数**：
   - 4路组相联 → 每组4块
   - 组数 = 512 / 4 = 128组 = 2^7
   - 组号 = 7位

4. **计算主存块数**：
   - 主存容量 = 1MB = 2^20B
   - 主存块数 = 1MB / 32B = 32768块 = 2^15

5. **计算标记位数**：
   - 主存地址 = 20位（1MB = 2^20B）
   - 标记 = 主存地址 - 组号 - 块内偏移
   - 标记 = 20 - 7 - 5 = 8位

**地址格式**：
```
| 标记Tag(8位) | 组号Set(7位) | 块内偏移Offset(5位) |
```

**映射规则**：
- 主存块号 mod 组数 = 组号
- 例：主存块号 = 100
  - 100 mod 128 = 100 → 映射到第100组
  - 可以放在第100组的任意一行（0/1/2/3行）

**优点**：
- 比直接映射冲突率低
- 比全相联映射硬件简单
- 折中方案，实际最常用

**缺点**：
- 硬件复杂度适中
- 仍存在一定冲突

---

### 三、映射表的有效位

#### 1. 为什么需要有效位？
- Cache初始化时，所有块都是**无效**的（没有数据）
- 标记（Tag）字段可能有任意值（可能是上次残留的数据）
- 如果不检查有效位，可能会**误判为命中**

#### 2. 有效位的作用
- **有效位 = 1**：该Cache块包含有效数据
- **有效位 = 0**：该Cache块为空或数据已无效

#### 3. 映射表结构

**直接映射映射表项**：
```
| 有效位(1位) | 标记Tag | 数据块 |
```

**组相联映射映射表项**：
```
| 有效位(1位) | 标记Tag | 数据块 |
```
（每组有多个这样的表项）

#### 4. 有效位的使用流程

**读操作**：
1. 根据地址找到Cache块
2. **检查有效位**：
   - 有效位 = 0 → 未命中，访问主存
   - 有效位 = 1 → 继续检查标记
3. 比较标记Tag：
   - Tag匹配 → 命中，返回数据
   - Tag不匹配 → 未命中，访问主存

**写操作**：
1. 根据地址找到Cache块
2. 检查有效位和标记
3. 如果未命中，从主存调入块，**设置有效位 = 1**
4. 写入数据到Cache

#### 5. 重要考点

⚠️ **必考点**：映射表必须要有一位有效位！

**原因**：
- 避免Cache初始化时的误判
- 区分有效数据和无效数据
- 确保Cache命中判断的准确性

**真题示例**：
> Cache的映射表中，每个映射项除了标记和数据外，还必须包含（ ）
> A. 替换算法标志  B. 有效位  C. 修改位  D. 以上都是
> 
> **答案**：B（有效位是必须的，修改位和替换算法标志是可选的）

---

### 四、Cache替换算法

1. **随机算法（RAND）**：随机选择替换块
2. **先进先出（FIFO）**：替换最早进入的块
3. **近期最少使用（LRU）**：替换最久未使用的块 ⭐最优
4. **最不经常使用（LFU）**：替换访问次数最少的块

---

### 五、Cache写策略

#### 1. 写直达法（Write Through）
- 同时写入Cache和主存
- **优点**：数据一致性好
- **缺点**：速度慢

#### 2. 写回法（Write Back）
- 只写入Cache，修改标志位
- Cache块替换时才写回主存
- **优点**：速度快
- **缺点**：实现复杂

## 3.4 虚拟存储器

### 一、基本概念

**虚拟存储器**：基于局部性原理，将主存和辅存统一管理，为用户提供比实际主存大得多的地址空间。

**局部性原理的应用**：
- **时间局部性**：程序倾向于重复访问最近使用过的数据和指令
  - 例：循环变量、频繁调用的函数
  - 应用：TLB缓存最近使用的页表项
  
- **空间局部性**：程序倾向于访问最近访问过的数据附近的数据
  - 例：数组顺序访问、指令顺序执行
  - 应用：预取相邻页面到主存

**虚拟存储器如何利用局部性原理**：
1. **页面调入**：只将当前需要的页面调入主存，其他页面留在磁盘
2. **页面置换**：根据局部性原理选择置换页面（LRU算法）
3. **预取机制**：提前将可能访问的页面调入主存
4. **TLB加速**：利用时间局部性，缓存最近使用的页表项

**效果**：
- 虽然主存容量有限，但通过局部性原理
- 可以保证**常用页面**在主存中
- 实现**逻辑上**的大容量存储

**页式虚拟存储**：
- 逻辑地址分为：**页号 + 页内偏移**
- 物理地址分为：**页框号 + 页内偏移**
- 通过**页表**进行地址映射

---

### 二、TLB（快表）

**TLB作用**：加速地址翻译过程

**访问流程**：
1. CPU给出虚拟地址
2. 先查TLB
   - 命中：直接得到物理地址
   - 未命中：查页表，同时更新TLB
3. 访问物理内存

**TLB命中率**通常很高（>95%）

---

### 三、页面置换算法

1. **最佳置换算法（OPT）**：理论最优，无法实现
2. **先进先出（FIFO）**：可能出现Belady异常
3. **最近最少使用（LRU）**：性能较好 ⭐常用
4. **时钟算法（Clock）**：LRU的近似实现

---

### 四、段式与段页式存储

**段式存储**：
- 按逻辑模块分段
- 地址结构：**段号 + 段内偏移**
- 便于共享和保护

**段页式存储**：
- 先分段，段内再分页
- 地址结构：**段号 + 页号 + 页内偏移**
- 兼具两者优点

---

## 3.5 外存储器

### 一、磁盘存储器

**磁盘结构**：
- **盘片**：多个同心圆磁道
- **磁头**：每个盘面一个
- **柱面**：所有盘面上相同半径的磁道

**磁盘访问时间**：
$$T = T_s + T_r + T_t$$

- $T_s$：寻道时间（移动磁头）
- $T_r$：旋转延迟（等待扇区转到磁头下）
- $T_t$：传输时间

---

### 二、RAID技术

**RAID级别**：
- **RAID 0**：条带化，提高速度，无冗余
- **RAID 1**：镜像，完全冗余，利用率50%
- **RAID 5**：分布式奇偶校验，平衡性能和冗余 ⭐常用
- **RAID 10**：镜像+条带化，高性能高可靠
