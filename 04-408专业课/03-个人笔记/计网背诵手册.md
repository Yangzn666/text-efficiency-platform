## 零|全局判断框架|先背这四张表，能拿下 40% 的题

### 0.1 七层职责一句话 + 设备归属

| 层 | 一句话职责 | 数据单元 | 典型设备 |
| --- | --- | --- | --- |
| 应用层 | 给用户干活（HTTP/DNS/FTP/SMTP） | 报文 | 主机、网关 |
| 表示层 | 格式转换、加密、压缩 | 报文 | — |
| 会话层 | 建立/管理/终止会话 | 报文 | — |
| 传输层 | **端到端**：应答、排序、流量控制 | 段 Segment | 主机、四层交换机 |
| 网络层 | **逐跳**：路由选择、拥塞控制、分组转发 | 分组 Packet | **路由器**、三层交换机 |
| 数据链路层 | **相邻节点间**：成帧、差错控制、流量控制、介质访问 | 帧 Frame | **交换机**、网桥、网卡 |
| 物理层 | 透明传输比特流 | 比特 Bit | **中继器、集线器** |

> hook: 关键词定位法——题干说「**相邻节点间**」→ 数据链路层；说「**端到端**」→ 传输层；说「**路由/拥塞**」→ 网络层；说「**比特/电气**」→ 物理层。

> warn: OSI 与 TCP/IP 别混：问「OSI 中可同时提供无连接 + 面向连接服务的层」= **网络层**（IP 无连接 + X.25 面向连接）；OSI 传输层**只**面向连接。只有 **TCP/IP 传输层**才同时有 TCP（连接）和 UDP（无连接）。

### 0.2 协议 / 服务 / 接口 三兄弟

| 概念 | 方向 | 定义 |
| --- | --- | --- |
| **协议 Protocol** | 水平 | **不同节点的对等实体**之间通信的规则或约定 |
| **接口 Interface（SAP）** | 垂直 | **同一节点相邻两层**之间交换数据的逻辑接口 |
| **服务 Service** | 向上 | 下层通过接口为上层提供的功能，上层看不见实现细节 |

> hook: 协议是"两国签的条约"（对等），接口是"上下楼的服务窗口"（相邻），服务是"窗口递出来的东西"。

### 0.3 协议 ↔ 承载关系（必背配对表）

| 协议 | 直接封装在 | 所在层 |
| --- | --- | --- |
| RIP | **UDP**（端口 520） | 应用层 |
| BGP | **TCP**（端口 179） | 应用层 |
| OSPF | **IP**（协议号 89，不走 TCP/UDP） | 网络层 |
| ICMP | **IP**（协议号 1） | 网络层 |
| IGMP | **IP**（协议号 2） | 网络层 |
| ARP | 直接封装在帧中（不属 IP） | 链路层与网络层之间 |
| DNS | **UDP**（端口 53，区域传送才用 TCP） | 应用层 |
| DHCP | **UDP**（67 服务器 / 68 客户端） | 应用层 |
| HTTP / FTP / SMTP / POP3 / IMAP | **TCP** | 应用层 |

> hook: 「**RIP 走 UDP、BGP 走 TCP、OSPF 直接骑 IP**」——RIP 像广播喇叭（UDP），BGP 像签合同（TCP），OSPF 自己就是网络层的官。

### 0.4 服务类型三分类（最容易全错的表）

| 服务类型 | 谁提供 | 记忆理由 |
| --- | --- | --- |
| **无连接 + 不可靠** | 以太网 MAC、UDP、IP | 发出去就不管，丢了不重传 |
| **有连接 + 不可靠** | **PPP** | LCP 建连接（所以要拨号），但不纠错、不编号、不流控 |
| **有连接 + 可靠** | TCP | 三次握手 + 确认重传 + 滑动窗口 |
| **无确认的无连接** | 信道可靠且实时性高时链路层的选择 | 可靠就不必确认，实时就来不及建连接 |

> warn: PPP 是**唯一**的"有连接但不可靠"，考试最爱设陷阱。别答成"可靠"。

### 0.5 封装链（OSI）

> chain: 应用/表示/会话层 → **数据** → 传输层加**端口号**成**段** → 网络层加 **IP 地址**成**分组** → 链路层加 **MAC + 帧定界 + 控制字段 + FCS** 成**帧** → 物理层转**比特**

> warn: 三个高频错项：①「链路层**仅**增加源/目的 MAC」错——还有帧定界符、控制字段、FCS；②「传输层封装成**帧**」错——是**段**；③「**表示层**加端口号」错——端口是**传输层**加的。

## 一|体系结构与分层|10 题 · 概念辨析

### 1.1 分层的三个目标（一个不是）

分层目标是：**提供标准语言**（统一术语）、**定义标准界面**（层间接口）、**增加功能之间的独立性**（各层可独立实现）。

> warn: **「定义功能执行的方法」不是分层目标**。分层只规定每层"做什么"（功能），绝不规定"怎么做"（实现）——这是分层能解耦的根本原因。

### 1.2 网络的基本性质

- 网络中的计算机是**自治**的：每台拥有**独立的操作系统**（不是共同 OS）
- 计算机之间通过通信链路和交换设备互联，**有联系但不互相干扰**
- 世界上第一个计算机网络 = **ARPAnet**（1969 年，第一个**分组交换**网），Internet 起源于 ARPAnet

> warn: **OSI/RM 只是 ISO 提出的理论参考模型**，用于教学和理解分层概念；**实际执行的标准是 TCP/IP 协议族**。OSI 因过于复杂、制定缓慢而未被广泛采用。题干说"OSI 是实际执行的标准"→ 错。

### 1.3 功能归属速判表

| 题干关键词 | 归属层 |
| --- | --- |
| 相邻节点间的流量控制、差错控制 | **数据链路层** |
| 端到端的应答、分组排序、流量控制 | **传输层** |
| TCP/IP 中处理可靠性、流量控制、错误校正 | **传输层** |
| 路由选择、拥塞控制、分组转发 | **网络层** |
| 为终端节点**隐蔽物理传输细节** | **物理层**（不是链路层！） |
| 封装成帧、介质访问控制 | **数据链路层** |

> hook: 「**隐蔽物理细节的是物理层自己**」——物理层向链路层屏蔽介质差异，所以这句话属于物理层功能，链路层的功能是成帧 + 差错 + 流控 + 介质访问。

### 1.4 存储转发时延（流水线重叠）

> formula: 分组从 A 到 B 的总时间 = 第一个分组的全程时延 + (分组数 − 1) × 每跳最慢环节时延

例：2 个 1000B 分组、链路 1Mb/s（发送时延 8ms）、路由器处理时延 10ms、忽略传播时延：

| 时刻 | 分组 1 | 分组 2 |
| --- | --- | --- |
| 0–8ms | A 发送 | — |
| 8–16ms | 到达路由器，处理中 | A 发送 |
| 16–18ms | 仍在处理 | 到达，**缓存排队** |
| 18–26ms | 发往 B | 路由器空闲，开始处理 |
| 26–28ms | B 收完 | 处理完 |
| 28–36ms | — | 发往 B → **36ms 全收完** |

> hook: 关键是**路由器处理完分组 1 就立刻能处理分组 2**（18ms，不用等分组 1 送到 B 的 26ms）——分组在链路上"流水线重叠"。

## 二|物理层与传输介质|14 题 · 计算 + 设备性质

### 2.1 三大公式（必背）

> formula: **奈奎斯特（无噪声理想信道）**：C = 2W · log₂V　　W 带宽(Hz)，V 码元离散级数

> formula: **香农（有噪声信道）**：C = W · log₂(1 + S/N)　　信噪比 dB = 10·lg(S/N)

> formula: **数据速率 = 波特率 × log₂V**　　波特率上限 = 2W

> warn: **两个条件同时给出时，必须取 min！** 例：二进制信号在信噪比 127:1 的 4kHz 信道 → 奈奎斯特 2×4000×log₂2 = **8000 b/s**，香农 4000×log₂128 = 28000 b/s → 实际最大 = **min = 8000 b/s**。只算香农选 28000 是经典错法。

> warn: **题目给的采样率可能超过 2W，是陷阱！** 例：无噪声 8kHz 信道、8 级信号、"每秒采样 24k 次" → 最大波特率受限于 **2W = 16k 波特**（不是 24k！）→ 16000 × log₂8 = **48 kb/s**。用 24k×3 = 72k 就掉坑了。

### 2.2 典型计算

| 题型 | 解法 | 答案 |
| --- | --- | --- |
| 波特率 1000 Baud，要 4 kb/s，求码元级数 V | 4000 = 1000 × log₂V → log₂V = 4 | **V = 16** |
| 4kHz、信噪比 127:1、二进制 | min(2W·log₂2, W·log₂128) = min(8000, 28000) | **8000 b/s** |
| 8kHz 无噪声、8 级、采样 24k | 2W = 16k 波特 × 3 bit | **48 kb/s** |

> hook: 反推级数时记住 **log₂V 必须是整数**：4 倍速率 → 16 级；2 倍 → 4 级。

### 2.3 影响数据传输速率的因素

影响：**信噪比**（香农）、**频率带宽 W**（两公式都有）、**调制速率/波特率**（乘 log₂V）。

> warn: **不影响数据传输速率的是「信号传播速度」**——它只影响**传播时延**，与 bps 无关。电磁波在铜线里跑多快，跟一秒能塞多少比特是两回事。

### 2.4 编码与调制方式

| 方式 | 全称 | 改变什么 | 载波个数 |
| --- | --- | --- | --- |
| **ASK** | 幅移键控 | 振幅 | 1 |
| **FSK** | 频移键控 | **频率** | **2**（两个不同频率分别表示 0 和 1） |
| **PSK** | 相移键控 | 相位 | 1 |
| **DPSK** | 差分相移键控 | 相位差 | 1 |

> hook: **只有 FSK 要 2 个载波**——"频移"就是要在两个频率之间跳，其他都是在一个载波上改振幅或相位。

### 2.5 传输方式与介质

- **计算机内部**（CPU↔内存、总线）用**并行传输**；**远距离通信**用**串行传输**
- 同步/异步是**时序方式**，与并行/串行是两个正交维度，不要混选
- **卫星通信**：覆盖广、易实现广播和多址；但**受气候影响显著**（雨衰、大气吸收）、GEO 高 36000km、传播时延约 **270ms**、**误码率并不低**、费用高

> warn: 「卫星通信不受气候影响、误码率很低」→ **完全错误**。看到"不受影响/很低"这种绝对化描述，先怀疑。

### 2.6 物理层设备（中继器 / 集线器）

| 结论 | 说明 |
| --- | --- |
| 中继器工作在**物理层**，仅作用于信号的**电气部分** | 不懂帧、不懂地址 |
| 中继器是**再生(regenerate)** 信号，不是**放大(amplify)** | 放大会同时放大噪声；再生是先判决再重建原始数字信号 |
| 集线器 = **多端口中继器**（中继器 2 口，集线器 4 口以上） | 半双工、所有端口同一冲突域 |
| 物理层设备互连的几个网段**仍是一个局域网** | 不隔离冲突域、不隔离广播域 |
| 互连网段数量**受 5-4-3 规则限制** | 最多 5 个网段、4 个中继器、其中 3 个可接主机 |

> hook: **5-4-3**：五段四中继三接机。超过就会因时延太大而检测不到冲突。

> warn: 「利用中继器扩大距离的原理是**放大**衰减信号」→ 错，是**再生**。这是真题原句陷阱。

### 2.7 网络层交换方式（虚电路 vs 数据报）

| 维度 | 虚电路 Virtual Circuit | 数据报 Datagram |
| --- | --- | --- |
| 连接 | **面向连接**（先建立） | 无连接 |
| 地址 | 建连时给完整地址，之后只带**短的 VCID** | **每个分组都带完整源+目的地址** |
| 转发依据 | VCID 查虚电路表 | 目的 IP 独立查路由表 |
| 顺序 | **保证按序到达** | **不保证顺序**（各路独立） |
| 路由 | 建连时定死一条 | 每分组独立选路 |
| 故障适应 | 差（链路断则整条虚电路废） | **强（可动态绕开故障节点）** |
| 带宽 | **不预先分配**（仍是存储转发、统计复用） | 不分配 |

> warn: 「虚电路**预先分配带宽**」→ 错。虚电路只是建立了逻辑连接和固定路径，资源仍是按需统计复用，不像电路交换那样独占带宽。

> hook: **故障率高的系统选数据报**——因为它能逐分组绕路。军队通信、可靠性优先的场景都用数据报。

- **路由器互连的多个局域网**：物理层、数据链路层、网络层协议**都可以不同**；**网络层以上（传输层及以上）必须相同**

> hook: 路由器能"翻译"下面三层，但端到端的高层协议必须一致，否则两台主机听不懂对方。

### 2.8 SDN 与 OpenFlow

| 结论 | 说明 |
| --- | --- |
| SDN 是一种**新型网络体系结构**（不是物理网络结构） | 核心思想：控制面与数据面分离 |
| OpenFlow 交换机基于**流表(Flow Table)** 转发 | 匹配多个首部字段 + 动作 |
| **控制器不在交换机中**，运行在远程服务器上 | 一个控制器可管多台交换机 |
| OpenFlow 是**控制面与数据面之间的接口协议** | 控制器用它下发流表 |

> warn: 「SDN 改变了网络的物理拓扑结构」/「控制器内置在交换机里」→ 都错。SDN 改的是**控制方式的体系结构**，交换机本身仍是转发设备。

## 三|数据链路层|39 题 · 最大重灾区（3.6 节独占 20 题）

### 3.1 链路层功能与服务选择

链路层四大功能：**封装成帧**（定义帧格式）、**差错控制**、**流量控制**、**介质访问控制**。

> warn: 「**为终端节点隐蔽物理传输的细节**」**不属于**链路层功能，那是**物理层**的功能。

| 需求场景 | 该选什么 | 理由 |
| --- | --- | --- |
| 信道可靠 + 实时性高 | **无确认的无连接服务** | 可靠就不必确认；实时就来不及建连接 |
| 避免**帧丢失** | **计时器超时重发** | CRC/海明码只检错纠错；帧编号只查重与失序 |
| 检测**重复帧** | 帧编号 | — |
| 检错 | CRC | 只检不纠 |
| 纠错 | 海明码 | 码距足够才可纠 |

> hook: 「**丢了才要重发，错了才要检错，重了才要编号**」——三种问题三种药，别拿检错码去治丢帧。

### 3.2 组帧与透明传输

| 方法 | 用在哪 | 规则 |
| --- | --- | --- |
| **零比特填充** | HDLC、同步 PPP | 发送方扫描，**每连续 5 个 1 就插入 1 个 0**；接收方反向删除 |
| **字符（字节）填充** | **异步线路的 PPP** | 数据中 0x7E → `0x7D 0x5E`；0x7D → `0x7D 0x5D` |

> hook: HDLC 组帧例：`01111100 01111110` → 前段 `011111`+`0`+`00`，后段 `011111`+`0`+`10` → **011111000 011111010**。**5 个 1 后必插 0**，插完接着往下数。

### 3.3 差错控制公式

> formula: **检错**：码距 d ≥ e + 1　　**纠错**：码距 **d ≥ 2t + 1**　　（t = 可纠正的错位数）

| 需求 | 最小码距 |
| --- | --- |
| 纠 1 位错 | d ≥ 3 |
| **纠 2 位错** | **d ≥ 5** |
| 检 e 位错 | d ≥ e + 1 |

> hook: 纠错要"多一倍再加一"，因为既要发现错误又要判断正确方向。

### 3.4 停止-等待协议效率

> formula: 信道利用率 **U = Td / (Td + RTT + Ta)**　　Td = 数据帧发送时延，Ta = 确认帧发送时延

> warn: 使停等效率**最低**的组合是「**距离很远 + 速率很高**」→ RTT 巨大而 Td 极小 → U 趋近 0。直觉相反的「距离远 + 速率低」其实 Td 也大，U 不一定低。

> hook: **停等最怕"路长车快"**——车一闪就发完了，剩下的时间全在等回信。

### 3.5 介质访问控制

| 协议 | 关键性质 |
| --- | --- |
| **CSMA/CD** | 只能**半双工**（要边发边听冲突）；争用期 = 最远两端点**往返**传播时延 **2τ** |
| **CSMA/CA** | 用于 802.11 无线；**要回 ACK**；**不能消除冲突只能减少**；信道空闲后仍需等 **DIFS + 随机退避** |
| **CDMA** | 解码 = 收到序列 S 与各站码片序列做**规格化内积** S·C/m；结果 **+1 发 1、−1 发 0、0 未发送** |
| **令牌环** | 无冲突、**适合负载重**（重负载下利用率高于 CSMA/CD） |

> hook: CDMA 解码三步：①收到序列 S 与目标站码片**逐位相乘求和**；②**除以码片长度 m**；③+1 → 发了 1，−1 → 发了 0，0 → 没发。

> warn: 令牌环适合**负载重**不是负载轻——轻负载时 CSMA/CD 几乎不冲突反而更快；重负载时 CSMA/CD 冲突剧增而令牌环零冲突。

### 3.6 以太网与 IEEE 802（20 题核心）

| 结论 | 细节 |
| --- | --- |
| IEEE 802 标准 = OSI 的**物理层 + 数据链路层** | 链路层再分为 **LLC**（逻辑链路控制）+ **MAC**（介质访问控制） |
| 以太网 MAC 提供**无连接的不可靠服务** | 无确认、不编号、不纠错 |
| 网卡（网络适配器）实现在**物理层 + 数据链路层** | 所以能处理 MAC 地址 |
| **MAC 地址由 ARP 解析**（不是 DNS） | 烧录在网卡 ROM 中，全球唯一 |
| 集线器连的共享式以太网**物理拓扑是星形**（逻辑总线） | **必须使用 CSMA/CD** |
| 以太网参考模型**只包括物理层和数据链路层** | 高层由主机负责 |

> warn: 三个高频错项：①「集线器以太网物理拓扑是**总线形**」错——是**星形**（Hub 在中心）；②「以太网**不一定**用 CSMA/CD」错——共享式**必须**用（光纤点对点全双工以太网除外）；③「MAC 地址由 **DNS** 解析」错——是 **ARP**。

### 3.7 二进制指数退避与争用期

> formula: 第 n 次冲突后，从 **0 ~ 2^k − 1** 中随机取 r，重传时延 = r × 2τ，其中 **k = min(n, 10)**

| 冲突次数 n | 随机范围 |
| --- | --- |
| 1 | 0 ~ 1 |
| 2 | 0 ~ 3 |
| 10 | 0 ~ 1023 |
| **11 及以上** | **0 ~ 1023**（k 封顶 10，不再增长） |

> hook: **11 次冲突 → 0~1023**。k = min(n,10) 封顶，所以第 11 次和第 10 次范围一样。

> formula: 冲突检测时间 = **往返传播时延**。例：两站各距 Hub 100m → 最坏单程 200m → 单程 1μs → **往返 2μs**

> warn: 100Base-T 的争用期是 **5.12μs**（对应 512 比特时间），计算时**要扣掉 Hub 的再生时延 1.535μs**，不能只按线缆长度算。

- **光纤以太网**：点对点连接、扩大网络覆盖范围、支持全双工、**不需要 CSMA/CD**（全双工不存在冲突）

### 3.8 无线局域网 802.11（CSMA/CA）

| 概念 | 结论 |
| --- | --- |
| 为什么用 CA 不用 CD | 无线**无法边发边收**（自信号强 10⁶ 倍），且存在**隐蔽站/暴露站**问题 |
| 是否要 ACK | **要**——链路层就确认，因为误码率高 |
| 能否消除冲突 | **不能**，只能减少（退避 + RTS/CTS） |
| 信道空闲后能立即发吗 | **不能**，仍需等 **DIFS + 随机退避** |
| 是否用退避算法 | **用**，与 CSMA/CD 一样有二进制指数退避 |

> formula: 帧间间隔长度：**SIFS < PIFS < DIFS**　　优先级越高等待越短

| 场景 | 用哪个 IFS |
| --- | --- |
| 发送 **RTS** 前（普通数据竞争） | **DIFS**（最长） |
| 发送 **CTS / DATA / ACK** 前 | **SIFS**（最短，保证同一会话连续占用信道） |

> hook: **S = Short 最短最急**（会话内部接力）；**D = DCF/Distributed 最长**（新会话要先排队）。

> formula: **NAV（网络分配向量）虚拟载波监听的预约时长 = 数据帧传输时延 + SIFS + ACK 帧传输时延**

> hook: NAV 要预留到"数据发完 + 等 SIFS + ACK 回完"，所以别人在这段时间内都闭嘴。

### 3.9 802.11 四个地址字段（由 To DS / From DS 决定）

| To DS | From DS | 含义 | 地址1 | 地址2 | 地址3 |
| --- | --- | --- | --- | --- | --- |
| 0 | 0 | 同一 BSS 内直接通信 | 目的 STA | 源 STA | BSSID |
| **1** | **0** | **STA → AP（发往 DS）** | **AP 的 MAC** | **源 STA** | **目的端（IP 下一跳/路由器）** |
| 0 | 1 | AP → STA（来自 DS） | 目的 STA | AP（BSSID） | 原始源 MAC |
| 1 | 1 | 无线网桥（4 地址帧） | 接收 AP | 发送 AP | 目的端 / 源端 |

> hook: 铁律——**地址1 永远是"这一跳的接收者"，地址2 永远是"这一跳的发送者"，地址3 是"IP 层的另一端"**。前两个随无线跳变化，地址3 不变。

> warn: STA 发给 AP 时：**A1 = AP，A2 = STA，A3 = 路由器（IP 下一跳）**。AP 转发给目标 STA 时：**A1 = 目的 STA，A2 = AP(BSSID)，A3 = 原始源 MAC**。**MAC 每跳重写、IP 不变**。

### 3.10 VLAN 与 802.1Q

| 结论 | 细节 |
| --- | --- |
| 802.1Q 标签插入位置 | **源 MAC 地址与类型字段之间**，共 **4 字节** |
| 标签内容 | TPID(2B) + **VID(12 位)** + 优先级(3 位) + CFI(1 位) |
| 最大帧长变化 | 1518 B → **1522 B**（**不是不变！**） |
| 同 VLAN 内通信 | 用**普通以太网帧**（不加标签） |
| VLAN 隔离什么 | **广播域**（交换机端口本身已隔离冲突域） |
| VLAN 优点 | 共享资源、简化管理、**提高安全性**、抑制广播风暴 |

> warn: **「链路聚合」不是 VLAN 的优点**；**VLAN 隔离的是广播域不是冲突域**（交换机每个端口早已是一个独立冲突域）。

> formula: 802.1Q 填充计算：**4B 标签计入载荷**。例：40B 的 IP 分组 + 4B 标签 = 44B，未达最小载荷 46B → **补 2B 填充**

> hook: 记「**载荷最小 46B，标签算在载荷里**」，所以加了标签后需要补的填充反而变少。

### 3.11 广播式网络的性质

- **共享广播信道**（对）
- **不存在路由选择问题**（对，所有节点都能收到）
- **可以不要网络层**（对，链路层即可完成通信）

> warn: **「不需要服务接入点 SAP」错**——SAP 是相邻层交换数据的接口，**任何**网络体系结构都必须有。

### 3.12 PPP 与 HDLC

| 协议 | 服务类型 | 透明传输方法 | 归属 |
| --- | --- | --- | --- |
| **PPP** | **有连接的不可靠服务** | **异步线路用字符填充**、同步线路用零比特填充 | TCP/IP 协议族 |
| **HDLC** | 面向比特 | 零比特填充 | **ISO 制定，不属 TCP/IP 协议族** |

PPP 三大组成：**LCP**（链路控制协议，建/配/测链路）、**NCP**（网络控制协议，配网络层）、认证（PAP/CHAP）。

> warn: PPP **不纠错、不编号、不流控**——它只保证"有连接"，不保证"可靠"。HDLC **不属于** TCP/IP 协议族。

### 3.13 交换机与转发（3.8 节 6 题）

| 结论 | 计算 |
| --- | --- |
| 交换机转发决策依据 | **目的 MAC 地址**（不是源 MAC，也不是 IP） |
| **直通交换(cut-through)** 最小转发时延 | 只需读完 **6B 目的 MAC = 48 bit** → 48 / 100Mb/s = **0.48μs** |
| 存储转发(store-forward) | 收完整帧 + 校验 FCS 才转发，时延大 |
| 交换表学习规律 | **源 MAC** 登记入表；查不到目的 MAC 则**洪泛**；集线器向除入口外所有口转发 |

> hook: **直通交换 = 只读门牌（6B MAC）就开送**；存储转发 = 整箱验完再送。

> formula: 吞吐量计算（2013 真题 38 同型）：全交换机 → **11 × 100 = 1100 Mb/s**；3 个系的交换机换成集线器 → 每系 3 台共享 100 + 2 台服务器各 100 = **500 Mb/s**；全部换成集线器 → 全网一个冲突域 = **100 Mb/s**

> hook: **交换机每端口独享带宽（可累加），集线器所有端口共享带宽（就一份）**。所以：一个冲突域 = 一份 100Mb/s。

- **本地通信量占比高**的局域网应放**交换机**（80% 流量在本局域网内 → 交换机把冲突域切开，收益最大）

> warn: 跨子网通信时，**MAC 地址每经过一个路由器就重写一次，IP 地址全程不变**（NAT 除外）。

## 四|网络层|29 题 · IP 地址与首部字段

### 4.1 IPv4 首部字段的计数单位（超高频）

| 字段 | 计数单位 | 关键点 |
| --- | --- | --- |
| **首部长度** | **32 比特 = 4 字节** | 最小值 5 → **20B**；最大值 15 → 60B |
| **总长度** | **8 比特 = 1 字节** | 最大 65535B |
| **片偏移** | **8 字节** | 偏移 100 → 原数据报第 **800** 字节 |
| TTL | 1（跳数） | 每过一个路由器减 1，为 0 丢弃并回 ICMP 超时 |

> hook: 「**首部按 4 数、总长按 1 数、片偏移按 8 数**」——单位从小到大是 总长度(1B) < 首部长度(4B) < 片偏移(8B)。

> warn: 片偏移单位是 **8B** 不是 1B！偏移字段值 100 对应原始数据的第 **100 × 8 = 800** 字节起。

### 4.2 分片计算流程

> chain: 数据部分 = 总长度 − 首部长度 → 每片数据必须是 **8 的倍数** → 向下取整到 MTU 内的最大 8 倍数 → 片偏移 = 前面累计数据 ÷ 8 → **MF：最后一片 = 0，其余 = 1**

例：总长 1580B、首部 20B（数据 1560B）、MTU = 800B → 每片最大数据 = 800 − 20 = 780 → 向下取 8 的倍数 = **776B**：

| 片 | 数据长度 | 总长度 | 片偏移 | MF |
| --- | --- | --- | --- | --- |
| 片 1 | 776B | **796B** | 0 | **1** |
| 片 2 | 776B | **796B** | 97（= 776 ÷ 8） | **1** |
| 片 3 | 剩 8B（1560 − 1552） | 28B | 194（= 1552 ÷ 8） | **0** |

> hook: 「**每片数据必须能被 8 整除**」是分片计算唯一的硬约束，先把 MTU 减去首部再向下取 8 的倍数。

### 4.3 IP 地址与子网划分（4.3 节 17 题，第二重灾区）

| 结论 | 说明 |
| --- | --- |
| **CIDR 的作用** | **有效分配 IPv4 地址空间** + **减少路由表条目**（路由聚合） |
| CIDR **不是** | 不是"划分子网"、不是 NAT、**不能彻底解决** IPv4 地址耗尽 |
| **划分子网的好处** | **减少广播域的大小**（限制广播范围） |
| 一台主机有多个 IP | 这些 IP 必须属于**不同的网络**（每个网络接口/身份一个） |
| **单播地址判断** | 主机位**非全 0 也非全 1**；全 0 = 网络地址，全 1 = 定向广播 |
| 路由表匹配原则 | **最长前缀匹配**（最具体的路由优先） |
| **默认路由** | 目的网络 **0.0.0.0** + 掩码 **0.0.0.0** |
| **受限广播地址** | **255.255.255.255**，路由器**不转发，直接丢弃**（只在本网络有效） |
| 定向广播 | 主机位全 1，路由器**可转发**到目标网络 |

> warn: **VLSM 陷阱**：题目问「划分 5 个子网」时借 3 位（2³ = 8 ≥ 5）；但若问「**可能的最小子网能有多少主机**」，可以借更多位 → 从 /24 借到 /31 甚至 /32。看清问的是"最少借几位"还是"最多能借几位"。答案示例：/24 网段中**可能的最小子网**可用主机数 = **254**（不划分时）。

> hook: 「**CIDR 管两件事：省地址 + 缩路由表**」。凡是说 CIDR "解决了地址枯竭"或"用于划分子网"的选项，都是错的。

### 4.4 ARP 与路由表

| 结论 | 说明 |
| --- | --- |
| ARP 功能 | **IP 地址 → MAC 地址**（同一局域网内**广播**请求、**单播**应答） |
| 同子网通信 | ARP 直接解析**目的主机**的 MAC |
| 跨子网通信 | ARP 必须解析**默认网关（路由器）** 的 MAC，不是目的主机 |
| 路由表确定输出端口 | 看**接口标识符**（下一跳地址指的是**下一个路由器**，不是本路由器的出口） |

> warn: 「下一跳 IP 地址」= **数据要送往的下一个路由器的 IP**，而不是本路由器的出接口地址。输出端口由**接口标识符**这一列确定。

### 4.5 NAT 与 ICMP

- **NAT 只换源 IP 地址（和端口），目的 IP 地址不变**
- **ICMP 报文直接封装在 IP 数据报中**（协议号 1），**由 IP 提供服务**，不走 TCP/UDP

| ICMP 报文类型 | 触发场景 |
| --- | --- |
| **源点抑制**（已废弃但考点保留） | **拥塞导致丢包** → 通知源端降速 |
| **超时** | **TTL 减到 0** |
| 目的不可达 | 路由器找不到路径 / 端口无对应进程 |
| 路由重定向 | 有更优的下一跳路由器 |
| 回送请求/应答 | ping |

> hook: 「**TTL 归零发超时，拥塞丢包发源点抑制**」——两个最常考的触发条件。

### 4.6 IPv6

| 维度 | IPv4 | IPv6 |
| --- | --- | --- |
| 地址长度 | 32 位 | **128 位** |
| 首部长度 | 20~60B 可变 | **固定 40B** |
| 首部字段数 | 多 | **更少**（简化处理） |
| 首部检验和 | 有 | **取消**（交给链路层和传输层） |
| 分片 | 主机和路由器都能分片 | **只有源主机能分片，路由器不分片** |
| 超 MTU 时路由器行为 | 分片 | **直接丢弃 + 回 ICMPv6「分组过大」** |
| 流标号 Flow Label | 无 | **有，用于 QoS/实时业务** |
| 地址表示 | 点分十进制 | **冒号十六进制**，可用 `::` 压缩连续 0 |

> hook: IPv6 三大"减法"：**减字段、减检验和、减路由器分片权**。路由器只管快转，出错让源主机自己改。

### 4.7 路由协议三巨头

| 维度 | **RIP** | **OSPF** | **BGP** |
| --- | --- | --- | --- |
| 算法 | **距离向量** | **链路状态（Dijkstra）** | 路径向量 |
| 承载 | **UDP** | **直接 IP** | **TCP** |
| 范围 | 自治系统内（≤15 跳） | 自治系统内（可分区域） | **自治系统之间** |
| 交换对象 | **只向相邻路由器**发 | 向 **AS 内所有路由器**洪泛 | 只与对等 BGP 发言人交换 |
| 交换内容 | **整个路由表** | **LSA 链路状态通告** | 可达路径信息 |
| 是否知道全网拓扑 | **不知道** | **知道本区域内完整拓扑** | 不知道 |
| 更新策略 | 收到更优路由**直接更新，无确认机制** | 链路状态变化立即洪泛 | 增量更新 |
| 好在哪 | 简单、开销小 | 收敛快、无跳数限制、支持等价多路径 | 策略丰富 |

> warn: **OSPF 划分区域(area)的主要目的是「减少洪泛交换的通信量」**（也减少路由表规模、限制拓扑变化影响范围），不是为了安全或节省地址。

> hook: RIP 像**邻里口耳相传**（只告诉邻居、说全部、不问真伪）；OSPF 像**全网广播地图**（每人自己算最短路）；BGP 像**国与国谈判**（讲政策不讲最短）。

### 4.8 DHCP 与移动 IP

> chain: DHCP 四步（DORA）：**Discover**（客户端广播找服务器）→ **Offer**（服务器提供地址）→ **Request**（客户端广播确认要哪个）→ **ACK**（服务器确认）

> warn: **DHCPREQUEST 是广播发送的：目的 IP = 255.255.255.255，源 IP = 0.0.0.0**——因为客户端此时**尚未获得合法 IP 地址**。Discover 和 Request 都是广播。

移动 IP 四阶段：

| 阶段 | 内容 |
| --- | --- |
| 1. **代理发现** | 移动节点通过 ICMP 路由通告发现归属代理 HA / 外部代理 FA |
| 2. **注册** | 移动节点向 **归属代理 HA** 注册转交地址（**不是向 FA 注册**） |
| 3. **分组路由** | HA 与 FA 之间建立**隧道**，把发往归属地址的分组转发到转交地址 |
| 4. **注销** | 移动节点回到归属网络后注销 |

> hook: 注册的对象永远是"**老家的管家 HA**"——因为要让 HA 知道"我现在在哪个外地地址"，才能替我转信。

### 4.9 拥塞分析

- 判断拥塞看**汇聚方向**：多条输入链路的数据同时涌向一条输出链路 → 该输出链路饱和 → 需要丢弃或源点抑制
- 拥塞控制是**全局性**的（网络层），流量控制是**端到端**的（传输层），两者别混

## 五|传输层|9 题 · 端口与 UDP 细节

### 5.1 端口与套接字

| 结论 | 说明 |
| --- | --- |
| **熟知端口（系统端口）** | **0 ~ 1023** |
| 登记端口 | 1024 ~ 49151 |
| 短暂端口（客户端临时） | 49152 ~ 65535 |
| TCP 和 UDP 的端口空间 | **相互独立**，同一端口号可**同时**存在于同一主机的 TCP 和 UDP 中 |
| **Socket 套接字** | **= IP 地址 + 端口号**，唯一确定互联网上一个通信端点 |

> hook: 「**Socket = IP + Port**」——IP 找到主机，端口找到进程，两者合起来才唯一。MAC 地址只在**局域网内**有效，不能用于互联网定位进程。

### 5.2 UDP 细节

| 字段/机制 | 结论 |
| --- | --- |
| UDP 首部 | 固定 **8 字节**（源端口、目的端口、长度、校验和各 2B） |
| **长度字段** | = **首部 8B + 数据**，**不含伪首部** |
| **校验和覆盖范围** | **伪首部 + UDP 首部 + 数据**（伪首部只参与计算，不传输） |
| 校验和算法 | **二进制反码求和，再取反码**；按 2B 对齐，不足补全 0 |
| **校验和结果为 0 时** | **必须转成 0xFFFF**（因为全 0 表示"未生成校验和"） |
| 伪首部内容 | 源 IP、目的 IP、0、协议号(17)、UDP 长度 |
| 收到差错数据报 | **直接丢弃**（不重传、不纠错、不通知） |
| 可靠性由谁负责 | **应用层**（用 UDP 的应用自己实现确认重传） |

> warn: 两个必考陷阱：①「UDP 长度字段包含伪首部」→ **错**，长度只算首部+数据；②「校验和算出全 0 就填 0」→ **错**，要填 **0xFFFF**，全 0 保留给"关闭校验和"。

> hook: 伪首部是"**借 IP 地址来验一遍有没有送错主机**"，只在校验和计算时临时借来用，绝不发送。

### 6.1 WWW 访问流程与时延计算

> chain: 浏览器输入 URL → **① 域名解析（DNS，在 TCP 连接之前！）** → **② TCP 三次握手** → **③ 发送 HTTP 请求** → **④ 服务器响应** → ⑤ 释放连接

> warn: **WWW 工作的第一步是域名解析**，发生在 TCP 连接建立**之前**。没有 IP 地址根本无法建立 TCP 连接。

> formula: 经典时延题（RTT = 10ms）：**最短 20ms**（DNS 已缓存 → TCP 握手 1RTT + HTTP 请求响应 1RTT）；**最长 50ms**（DNS 递归查询 3RTT = 30ms + TCP 10ms + HTTP 10ms）

> hook: 「**缓存命中就只剩 2 个 RTT；缓存全丢就要 3 + 1 + 1 = 5 个 RTT**」。

### 6.2 DNS

| 结论 | 说明 |
| --- | --- |
| DNS 传输层协议 | **UDP（端口 53）**，无连接；只有**区域传送**用 TCP |
| 域名与 IP 的关系 | **不是一一对应**——一个域名可对应多个 IP（负载均衡/CDN），一个 IP 也可承载多个域名（虚拟主机） |
| **权限域名服务器** | 负责**其管辖区域内**主机名 → IP 的映射，能给出最终答案 |
| 根域名服务器 | **只返回顶级域名服务器的地址**，不直接给出主机 IP |
| 顶级域名服务器 | 返回权限域名服务器的地址 |
| **本地域名服务器** | 主机解析软件的**代理**，负责递归查询；主机只需知道它的 IP |
| 主机解析软件需要知道 | **只需本地域名服务器的 IP**（根和父节点的 IP 由本地 DNS 维护） |
| 迭代查询次数 | **最少 0 次**（本地 DNS 已缓存）、**最多 = 层级数** |

> formula: 迭代查询最多次数：本地 DNS → 根 → 顶级(.com) → 权限(abc.com) → 次级权限 = **4 次**

> hook: 「**根服务器是问路人，只告诉你去哪个路口问，绝不亲自带你去**」。

> warn: DNS 用 **UDP** 不是 TCP——这是与 FTP/SMTP/HTTP 的关键区别。凡问"下列哪个协议使用无连接服务"，选 **DNS**。

### 6.3 FTP

## 八|费曼新增血点|cn-01 首诊（2026-09-17）

### 8.1 五层套壳链 + 数据单位口诀（AM / TS / NP / DF / PB）
```
[应用层]       报文 message           (AM)
    ↓ TCP/UDP 头 (端口号 / 序号)
[传输层]       报文段 segment         (TS)
    ↓ IP 头 (源 IP / 目的 IP / TTL)
[网络层]       分组 packet            (NP)
    ↓ 帧头 + 帧尾 (MAC + FCS)
[数据链路层]   帧 frame               (DF)
    ↓ 变比特流
[物理层]       比特 bit               (PB)
```
**方向锁死**：**上层的数据 = 下层的载荷**，每往下一层套一层壳（帧还有尾）。

> warn: "帧封装后形成分组"**完全说反**——正确是"**分组装进帧**"（分组是被装的东西，帧是外面的箱子）。信封比喻：信（报文）→ 装进信封（段）→ 装进包裹（分组）→ 装进卡车货位（帧）→ 卡车运走（比特）。

### 8.2 TCP/IP 四层合并（**两组**都合并！）
TCP/IP = **应用层**（合 OSI 应用+表示+会话 三层）/ **传输层** / **网际层 IP** / **网络接口层**（合 OSI 数据链路+物理 两层）

> warn: 常见错答"数据链路+物理合并成网络接口层"只答了一半。**上三层也合并到应用层**，从 OSI 七层压到 TCP/IP 四层是**两组同时合并**的结果。

### 8.3 透明传输（**数据链路层**专属，不是传输层）
**是什么**：让上层（网络层）**不感知"某些比特组合在链路上传不了"** 这个限制。

**为什么需要**：以太网/HDLC 帧靠标志字节 **0x7E = 01111110** 定头定尾。若数据字段里刚好出现 0x7E，会被误认成帧边界。

**怎么做**：链路层用 **0x7D 转义字符填充**：
- 数据里的 `0x7E` → 发送时替换成 `0x7D 0x5E`
- 数据里的 `0x7D` → 发送时替换成 `0x7D 0x5D`
- 接收端逆操作还原

网络层看不到这个过程 → "任何比特组合都能传" = 透明。

> hook: **透明 = 上层看不见底层的限制**。不是"看不见底层的存在"（那是"服务访问点 SAP 屏蔽实现细节"的另一种表述）。

### 8.4 时延带宽积 BDP
> formula: **BDP = 带宽 × 传播时延**，**单位 = bit**（不是 bps 不是秒）

**物理含义**：**链路当前"飞"着多少比特**（也叫"比特管容量 / pipelining capacity"）。发送方发出 BDP 个 bit 时，第一个 bit 才刚到达接收方。

**典型题**：GEO 卫星 1 Mbps + 传播时延 270 ms → BDP = 10⁶ × 0.27 = **270,000 bit**。要"填满"这条链路让 B 连续收到，TCP 窗口至少 270,000 bit，否则带宽浪费。

**水管类比**：带宽 = 每秒流过多少水（bps）；传播时延 = 一滴水从头到尾的时间（s）；相乘 = **管里同时在流的水量**（bit）。

### 8.5 网络三硬件 + 通信/资源子网
**硬件三大件**（**不是"总线"**——那是**计组** CPU 内部概念）：
- **端系统 Host**（PC / 服务器 / 手机）——**产生和消费数据**
- **通信链路 Transmission Media**（双绞线 / 光纤 / 无线电）——承载比特
- **分组交换设备 Packet Switch**（路由器 / 交换机）——**在端系统之间转发**

> warn: "计算机、总线、路由器"是常见错答。总线 = 计组里 CPU 与内存/IO 之间共享的一组信号线（数据/地址/控制总线），不是计网"通信链路"。层次差得远。

**逻辑功能两分**（考研常考填空）：
| 部分 | 内容 | 职责 | 记忆 |
|---|---|---|---|
| **通信子网** | 链路 + 交换设备（下层） | 数据传输 / 转发 / 通信控制 | **运货的物流网** |
| **资源子网** | 主机 + 终端 + 软件 + 数据（上层） | 数据处理 / 计算 / 资源共享 | **千家万户和货** |

**填空模板**：计算机网络从逻辑功能上可分为 **通信子网** 和 **资源子网** 两部分，前者负责 **数据传输与转发**，后者负责 **数据处理与资源共享**。

### 8.6 PAN / LAN / MAN / WAN 四范围
| 名字 | 范围 | 典型 |
|---|---|---|
| **PAN** Personal 个人区域网 | **米级** | 蓝牙、Zigbee、USB 直连 |
| **LAN** Local Area 局域网 | 百米-几公里 | 校园/企业以太网、Wi-Fi |
| **MAN** Metropolitan 城域网 | 城市级几十-几百 km | 有线电视网、城域光纤 |
| **WAN** Wide Area 广域网 | 跨国大洲 | 因特网骨干 |

### 8.7 三种交换技术（**打电话 / 寄信件 / 寄快递拆包**）
| 交换 | 比喻 | 建立 | 传输 | 特点 | 代表 |
|---|---|---|---|---|---|
| **电路交换** | **打电话** | 先建立独占通路 | 全程占线 | 效率高、**线路利用率低**、实时 | PSTN 传统电话网 |
| **报文交换** | **寄信件** | 无需建立 | 整条报文**一次性存储-转发** | 延迟大、要中间大存储 | 早期电报（已基本淘汰） |
| **分组交换** | **寄快递拆包** | 无需建立 | **切成小分组**独立选路 + 存储-转发 | 利用率高、抗毁、支持突发 | **互联网 IP** |

**分组交换再细分两类**：
- **数据报 datagram**（无连接）：每分组独立选路，可能乱序 → **IP**
- **虚电路 virtual circuit**（面向连接）：先建逻辑通路，分组按同路线 → X.25 / 帧中继 / ATM

> warn: **虚电路"面向连接"但**不预分配带宽**（仍统计复用）。跟电路交换的"独占通路"要分清。

**四组顺序**（记住就行）：
- **同带宽同距离时延**：电路 < 分组 < 报文
- **信道利用率**：分组 > 报文 > 电路
- **实时性**：电路最好（因为独占通路无排队）
- **可靠性 / 抗毁性**：分组最好（分布式路由，一条断能绕）

### 8.8 设备分层归属（**中链交，路在网**）
| 设备 | 层 | 判断依据 |
|---|---|---|
| **中继器 repeater / 集线器 hub** | 物理层 | 只看/再生比特流，**不懂 MAC** |
| **网桥 bridge / 交换机 switch** | 数据链路层 | 看 **MAC 地址**转发帧 |
| **路由器 router** | 网络层 | 看 **IP 地址**选路转发分组 |

> warn: "转发器"不是标准词。若指 **repeater（中继器）** = 物理层；若指 **switch（交换机）** = 链路层。考研题里出现 repeater / 集线器 → 物理层；bridge / 交换机 → 链路层；路由器 → 网络层，三挡位必分。

> warn: 中继器是**再生**信号（重建 0/1），不是**放大**信号（放大会连带放大噪声）。这是十大反直觉陷阱第 2 条。

### 8.9 带宽大 ≠ 时延小（经典判断题）
**错误命题**："带宽大的网络，从 A 到 B 的时延一定小。"

**反例**：
- **GEO 卫星** 1 Gbps 带宽 + 36000 km × 2 距离 → **传播时延 ≈ 250-280 ms**，比地面 ADSL 几 Mbps 但 20 ms 时延**高 10 倍以上**
- **跨洋海底光缆** 10 Gbps + 5000 km → 传播时延 = 5000 km / 200,000 km/s = **25 ms**，比局域网 100 Mbps + 100 m 的 0.5 μs **高 5 万倍**

**根因**：时延分四块（发送/传播/处理/排队），**带宽只影响发送时延**，另外三块（尤其传播时延）跟带宽**无关**。

|---|---|

| 传输层单位是"报文" | 传输层 = **报文段 segment**；"报文"是**应用层** |
| 网络层单位是"报文" | 网络层 = **分组 packet** |
| 物理层单位是"字节" | 物理层 = **比特 bit**（字节 = 8 bit 是数据单位不是信号单位）|

### 9.2 奈奎斯特 vs 香农 谁管什么（首诊整块忘）

|---|---|---|---|---|

### 9.3 曼彻斯特编码：波特率 = 2 × 比特率
曼彻斯特每个比特**中间必跳一次**，用**2 个码元**表示 1 比特 → 码元速率（波特率）翻倍。

> formula: 比特率 10 Mbps → 波特率 **20 MBaud**（单位是 Baud/兆码元每秒，别写"码元/s"）。代价：频带宽度被占一倍。

### 9.4 光纤为什么抗电磁干扰
光纤传的是**光**，不是电信号 → 电磁干扰（都是电的）根本耦合不进来。

> warn: 单模光纤（激光、直线、远距离、细芯）vs 多模（LED、反射、短距、粗芯）。链路层"传光"= 免疫 EMI，这条爱考。

### 9.5 CSMA/CD 四步流程 + 硬件在网卡（首诊全错）
CS = 载波侦听（Carrier Sense），CD = 冲突检测（Collision Detection）。四步锁死顺序：

> chain: **先听后发 → 边发边听 → 冲突停发（发一串干扰码 jam 强化冲突）→ 随机重发（二进制指数退避）**

> warn: 这套逻辑烧在**网卡（NIC）**里，不是路由器（路由器 = 网络层）。首诊误答"路由器"，重点砸。

### 9.6 无线为什么改用 CSMA/CA 而不是 CD（原因别记反）
**不是因为"无线冲突概率小"**。真原因：无线站**自己发送时收不到/测不出冲突**——收发信号强度差太大 + **隐蔽站问题**，CD 在物理上做不了，只能**事前避免**（ACK、RTS/CTS 预约）。

> hook: **有线能边发边听（CD），无线听不见只能提前躲（CA）**。

**冲突域 / 广播域计数**（这条答对了，保持）：
| 设备 | 冲突域 | 广播域 |
|---|---|---|
| 8 口**集线器**（物理层） | **1**（全端口共享） | 1 |
| 8 口**交换机**（链路层） | **8**（每端口一个） | 1（默认同一广播域） |

### 9.8 GBN vs SR 出错怎么重传（首诊即对，巩固）
| 协议 | 出错时重传 | 接收方乱序帧 | 窗口 |
|---|---|---|---|
| **停止-等待** | 只重传这一帧 | —— | 发 1 等 1，利用率低 |
| **GBN 后退 N 帧** | 出错帧**及其后所有已发帧**全部重发 | **按序收、乱序丢弃**（不缓存） | 发送窗大，接收窗=1 |
| **SR 选择重传** | **只重传出错那一帧** | **乱序缓存**，等补齐再交付 | 收发窗都 >1 |

> warn: "GBN 接收方能乱序缓存"是**错的**——那是 SR 的本事。

### 9.9 以太网最小帧长 64 B ↔ 争用期 2τ（首诊忘）
帧的**发送时间必须 ≥ 争用期（碰撞窗口 = 2τ，信号在最远两端来回一趟）**。否则帧先发完、冲突信号才回来 → **漏检冲突**。所以规定最小帧长 **64 字节** = 目的 6 + 源 6 + 类型 2 + 数据 46 + FCS 4；有效数据不足 46 字节就**填充 pad** 凑够。

> hook: **64 字节下限是在跟争用期赛跑**；反向，争用期 2τ 也限定了以太网最大跨度。

### 9.10 陷阱补丁（cn-02 + cn-03 首诊新加）
| 你以为 | 实际上 |
|---|---|
| 信道分"双工/半双工/双工" | **单工 / 半双工 / 全双工**；对讲机半双工、打电话全双工 |
| 信噪比用奈奎斯特 | 有噪声、给信噪比 → **香农**；无噪声、给电平级数 → 奈奎斯特 |
| 曼彻斯特波特率 = 比特率 | **波特率 = 2 × 比特率**（每比特 2 码元），10 Mbps → 20 MBaud |
| CSMA/CD 在路由器 | 在**网卡**；且"冲突概率小"不是无线用 CA 的原因 |
| 无线用 CA 因为冲突少 | 因为**发时测不出冲突**（强度差 + 隐蔽站），只能事前避免 |
| 交换机记目的 MAC | **学习记源 MAC，转发查目的 MAC** |
| GBN 接收方乱序缓存 | GBN **乱序丢弃**，SR 才乱序缓存 |
| 帧可以任意短 | 最小 64 B，发送时间要 ≥ 争用期 2τ 否则漏检 |
